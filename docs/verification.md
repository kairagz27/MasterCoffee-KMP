# Проверка — 25 октября 2026

Отчёт отделяет выполненные проверки от настроенных тестов и непроверенных платформ. Предыдущий отчёт сохранён в [архиве 24 октября](verification-2026-10-24.md); его результаты не заменяют повторную проверку нового кода.

## Исправления этого этапа

- Платформенные конструкторы, Settings, Keystore/Keychain, JSON кеша и durable commits перенесены за последовательную фоновую границу `BackgroundStorage`. Ошибка сохранения видна пользователю; формат существующих корзин и pending сохранён.
- Поколение запросов, отмена работ аккаунта и немедленный busy защищают от позднего входа и двойных действий. Back, черновик параметров и выбранная навигация восстанавливаются; staff/customer разделены.
- Очередь кабинета использует cursor; новый поиск сразу убирает действия старого заказа. Добавлены безопасное восстановление ошибок и удержание клавиатурного фокуса.
- API отклоняет неоднозначный регистр, дубликаты JSON и вложенный null. Регистрация атомарна. CLI создаёт нового сотрудника без повышения существующего покупателя; секреты можно передать файлами.
- Backup и fingerprint читают один PostgreSQL snapshot; restore проверяет сохранённый baseline, quotes и последовательности. Подготовлен отдельный HTTPS-шаблон с внешней verify-full PostgreSQL.
- R8/resource shrinking включены, release требует явный HTTPS URL. Найденный `StaticLoggerBinder` исправлен matching `slf4j-nop:1.7.36`, без подавления ошибок R8. Android хранит только Application context; правила cloud/device-transfer исключают приватные данные.

## Xiaomi 15 / Android 16

Физический Xiaomi 15 (24129PN74G), API 36, security patch 2025-12-01 подключён и авторизован. Проверены `adb reverse tcp:8080 tcp:8080`, установка `adb install -r` без удаления данных, обычный холодный запуск настоящего MainActivity и отображение формы авторизации. Локальная сборка использует URL USB reverse.

HyperOS 3.0 запрещает `adb shell input` с `SecurityException: INJECT_EVENTS`. Пользователь включил настройку безопасности и физически переподключил кабель; свежая одиночная проверка всё ещё отклонена. Instrumentation запускает runner, но открытие его Activity отменяется системой с `result 102`, тогда как обычный shell-start MainActivity имеет result 0. Зависшие попытки завершены только `am force-stop` своего пакета. Их `Process crashed` после принудительного завершения не выдаётся за естественный крэш приложения. Ни очистка данных, ни uninstall, ни обход ограничений ОС не выполнялись.

Пользователь вручную создал на телефоне заказ **MC-001109**: американо 350 мл с карамелью, 990 − 30 (3%) = **960 ₸**. Настоящий кабинет нашёл его по номеру, подтвердил тестовую кассовую оплату и прошёл accepted → preparing → ready. Xiaomi показал «Готов к выдаче / Оплачен», затем после выдачи в кабинете сам получил «Выдан / Оплачен» и строку истории. В профиле фактически показан **1 завершённый заказ с напитками**, что совпало с одной записью ledger в PostgreSQL. Это реальный совместный сценарий: пользователь нажимал на телефоне, сотрудник управлял кабинетом, состояния сняты через read-only ADB. Реальные деньги не списывались. [Доказательства кабинета](../admin/evidence/2026-10-25/phone-cabinet/journey.json).

Публичные снимки не содержат имени/email покупателя. Профиль с персональными данными хранится только в игнорируемом локальном evidence. Первые две попытки screenrecord оказались статичными снимками готовности и исключены. Финальная [непрерывная запись MC-001111](evidence/2026-10-25/hybrid-handoff.mp4) действительно содержит готовность → выдачу примерно на 23-й секунде: 61,77 с, 720×1600, 133 230 байт. Исходный MP4 не преобразовывался, проверено 63 кадра без персональных данных покупателя; [метаданные проверки](evidence/2026-10-25/video-proof.json). Создание заказа показано отдельно в галерее снимков.

В промежуточной сборке `02713ac` после установки `-r` и нового процесса настоящие Keystore/локальное хранение восстановили тот же аккаунт, экран PROFILE и счётчик **1**. Сравнение идентичности выполнено по SHA email в приватном evidence, само значение не опубликовано. В коротком окне logcat этого PID нет AndroidRuntime:E; это не общий вывод об отсутствии всех ошибок.

На этой сборке отдельно выполнен реальный loss-response/process-death тест. Loopback proxy передал создание серверу, получил HTTP 201 и удержал ответ дольше client deadline. Xiaomi показал тайм-аут с сохранённой корзиной. После `force-stop` и обычного старта настоящая durable корзина/pending восстановилась с кнопкой «Проверить создание заказа». Пользователь нажал её и получил **тот же MC-001110**. Read-only SQL: количество заказов владельца 1 → 2 после потерянного ответа → **2 после retry**; SHA-256 idempotency key/quote/request совпали, ledger остался **1**. Пользователь затем отменил неоплаченный MC-001110, что подтверждено настоящим экраном. Proxy остановлен, USB reverse возвращён напрямую на API 8080. [SQL proof](evidence/2026-10-25/recovery-proof.json), [тайм-аут](evidence/2026-10-25/09-timeout-pending.png), [pending после нового процесса](evidence/2026-10-25/10-pending-after-process-restart.png), [отмена](evidence/2026-10-25/12-cancelled-recovery-order.png).

После обратной связи владельца восстановлен гибрид исходного дизайна: шторка, плавающая навигация/тени, оригинальный логотип и фотофон лояльности. В этой версии `3f082dd` полный физический цикл повторён с **MC-001111**: эспрессо 30 мл, 890 − 27 (3%) = **863 ₸**. Сняты настоящие светлые экраны created → ready/paid → completed/paid, обновление выдачи получено polling без дополнительного нажатия. Логотип, тёмные системные иконки на светлом фоне и отступы видны корректно. [Галерея](evidence/2026-10-25/index.html), [кабинет](../admin/evidence/2026-10-25/phone-hybrid-cabinet/journey.json). Владелец подтвердил выбранный гибрид. После удаления повторяющихся настроек профиль с того же аккаунта восстановлен с **двумя** чеками и скидкой 3%; верх профиля снят отдельно в приватное evidence. Read-only SQL подтверждает три заказа владельца (1109/1111 completed, 1110 cancelled) и ровно две записи ledger. Язык/тема доступны только в шторке, профиль содержит аккаунт, лояльность и выход.

На Xiaomi фактически видны светлая и тёмная темы; полный набор RU/KK/EN × system/light/dark отдельно на телефоне не пройден. Также не подтверждены физическая смена A/B, увеличенный шрифт/клавиатура, TalkBack и камера. После последнего подтверждённого профиля с двумя чеками телефон оказался на пустой форме входа; logout HTTP 204 зарегистрирован до попыток автоматического оператора. Accessibility-пробы не нашли ожидаемых элементов и завершились до нажатий/ввода, поэтому вход B на Xiaomi не заявляется. Данные не очищались, приложение не удалялось. По просьбе владельца дальнейшие ручные действия не запрашивались.

Отдельный CI-тест на Android 16 проверяет смену аккаунтов через настоящий MainActivity и реальные платформенные хранилища: UI-регистрация A/B, заказ и корзина A, выход, пустые заказы/корзина и нулевая лояльность B, восстановление B новым MainActivity из Keystore, возврат A и его история. Это проверка native Android на эмуляторе, а не подмена физической проверки Xiaomi. Macrobenchmark/профилирование в подходящей сборке не выполнено; численные утверждения о скорости отсутствуют.

Для полного исходного SHA `5bc8a9d4e32b6588752b27fb481b7aaee88f869d` [CI 40171565550](https://github.com/kairagz27/MasterCoffee-KMP/actions/runs/40171565550) прошёл **все пять jobs**. Android 16 runner завершился `OK (6 tests)` и четырьмя обязательными маркерами: `masterCoffeeLaunchComplete`, `masterCoffeeLiveOrderComplete`, `masterCoffeeHybridUiComplete`, `masterCoffeeNativeAccountsComplete`. Скачанный UI artifact содержит 16 настоящих Android снимков, instrumentation log и пустой crash log; холодная форма входа, пустая история B, восстановленный профиль B и светлая тема с увеличенным шрифтом просмотрены отдельно.

Эти шесть кейсов проверяют native A/B/Keystore, настоящий MainActivity cold/rotation/background, UI-заказ с реальным API до выдачи/лояльности, управляемые навигацию/поворот/Back/logout, сетевую ошибку с восстановлением и гибридную шторку с RU/KK/EN, system/light/dark и шрифтом 135%. Предыдущая гибридная версия `3f082dd` также прошла [все пять jobs и пять UI tests](https://github.com/kairagz27/MasterCoffee-KMP/actions/runs/40166630827). При добавлении шестого теста обнаружен сбой тестовой обвязки во время recreate: обращение к `rule.activity` из SideEffect после уничтожения Activity. Тестовая композиция теперь использует свой `LocalActivity` с проверкой `isDestroyed`; повторный полный запуск прошёл.

Ранее CI обнаружил release/R8 `StaticLoggerBinder` и несовпадение UI-селектора `Cherry` с подписью, включающей цену. Обе ошибки исправлены и повторно проверены; сбор evidence выполняется и при неудаче. Успешный build не считается выполненным UI-сценарием.

Pipeline содержит пять jobs: backend с PostgreSQL/race; OpenAPI/Node/config; Android common/Lint/debug/test/release R8; Compose e2e + restart/backup/restore; отдельный Android 16 emulator с управляемыми Compose tests, реальным MainActivity smoke и настоящим API/PostgreSQL. Live/UI runner требует явных completion markers и JUnit PASS; нулевой exit code shell не достаточен. Сборки, отчёты и UI-снимки публикуются отдельными artifacts. Финальный SHA и его статус проверяются после последнего push.

## Среда, публикация и ограничения

Docker Desktop восстановлен штатным `docker desktop restart`; повреждённый BuildKit snapshot обойдён отдельным именованным builder без удаления прежнего cache/default builder. Локальные Compose и backup доказательства получены после восстановления, отдельно от Linux CI. Свои тестовые containers остановлены с сохранением volumes; чужие сервисы не затрагивались. Для телефона оставлены native API 8080 и PostgreSQL 18 на loopback 55433. Пользовательские AVD не удалялись, отклонённая ранее массовая очистка кешей не повторялась.

iOS не собирался и не запускался: среда Windows без macOS/Xcode. Сохраняются Darwin/Keychain и iOS source sets; просмотр исходников не заменяет native verification. До публичного пилота остаются email verification/reset, monitoring/retention, возвраты, нагрузка, реальный TLS и production signing. За nginx auth limiter видит общий IP, что требует решения для многопользовательского публичного запуска.

Работа опубликована в `codex/local-mvp`, [PR #1](https://github.com/kairagz27/MasterCoffee-KMP/pull/1); [проверки текущей ветки](https://github.com/kairagz27/MasterCoffee-KMP/actions/workflows/ci.yml?query=branch%3Acodex%2Flocal-mvp) показывают результаты после финального обновления документации. PR оставлен draft: физическая смена аккаунтов на Xiaomi остаётся неподтверждённой из-за ограничений HyperOS, хотя native Android CI этот сценарий проходит. Merge/force push не выполняются; исходный отдельный backend checkout сохранён.
