## Порядок и границы изменения

Сначала единый API-контракт, схема, авторизация и каталог; затем атомарные заказы, QR и рабочее место сотрудника; затем клиент и лояльность; в конце тесты PostgreSQL, реальный обмен двух ролей, Compose, APK и CI.

Изменения затрагивают весь мобильный путь данных и новый backend. Совместимость со старым Firebase-клиентом не поддерживается: новый API имеет префикс /api/v1. Статические изображения остаются ресурсами, цены и статусы — только серверными данными. MC Coins, рефералы и промокоды выключаются, поскольку исходные обещания не реализованы сквозным образом.

Откат к старой версии выполняется выбором исходного Git commit в отдельном checkout. Данные PostgreSQL перед изменением схемы сохраняются pg_dump; восстановление сначала проверяется в отдельной БД. Удаление Docker volume необратимо без резервной копии. Миграции предназначены для новой локальной БД; перенос живых Firebase/старых production-данных не разрешён этим изменением.
