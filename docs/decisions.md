# Решения и компромиссы

## Один API и одна PostgreSQL

Цена, права, заказ, оплата и лояльность проверяются в Go service и фиксируются транзакционно. Отдельные сервисы и брокер сообщений не нужны для текущего масштаба. Позиции сохраняют снимок данных; каталог можно редактировать без переписывания истории.

## Один Compose-модуль с явными пакетами

`domain`, `data` и `presentation` отделяют правила, транспорт/хранение и интерфейс без дополнительного графа Gradle-модулей. Платформенные engines, Keystore/Keychain и Back находятся в Android/iOS source sets. Выделение модуля оправдано, когда появится независимая сборка, повторное использование или команда с отдельной ответственностью.

## Последовательное хранение вне Main

Durable cart и pending key уже имеют установленный формат. Фоновая сериализованная граница `BackgroundStorage` сохраняет формат и синхронные гарантии записи, не блокируя главный поток. Mutex защищает порядок записи/очистки. Это небольшой набор настроек и одна корзина на аккаунт; отдельная SQL-база на телефоне пока не решает дополнительную задачу.

Гарантия важнее оптимистического сообщения: pending key сохраняется до HTTP, корзина очищается после подтверждения сервера, а ключ удаляется после успешной очистки корзины. Ошибка записи не превращается в успешное оформление. Поколение сессии и отмена корутин предотвращают публикацию поздних ответов предыдущего аккаунта.

## Управляемые UI-тесты и отдельный реальный сценарий

Compose tests используют изолированные данные и хранилища, чтобы воспроизводить тайм-ауты, ошибки, Back и пересоздание Activity. Отдельный opt-in instrumentation-сценарий использует настоящий HTTP API и PostgreSQL, создаёт собственный тестовый аккаунт и проходит оплату/выдачу через API сотрудника. Он не очищает данные существующего пользовательского аккаунта.

CI Android 16 emulator даёт воспроизводимую проверку настоящего Android UI. Он не доказывает поведение HyperOS, физической камеры, TalkBack или измеренную производительность Xiaomi. Эти результаты указываются отдельно.

## Release проверяется без вымышленного сервиса

Release требует явный HTTPS API URL и не содержит default production endpoint. R8 и resource shrinking включены. В CI `https://localhost/api/v1` применяется только как вход конфигурационной проверки компиляции; успешная release-сборка не означает проверенного HTTPS-сервера или готовой production-подписи.

Android-приложение явно включает `slf4j-nop:1.7.36`, соответствующий транзитивному SLF4J API Ktor. Это закрывает найденный R8 отсутствующий `StaticLoggerBinder` без `-dontwarn` и без вывода запросов клиента в лог. [SLF4J описывает matching binding](https://www.slf4j.org/codes.html#StaticLoggerBinder); версия 2.x здесь не подставляется вместо 1.7.

## Простая кассовая оплата

Сотрудник подтверждает реально полученную оплату. QR — ограниченная по времени ссылка на серверный заказ; резервный номер не требует камеры. Эквайринг, возвраты, MC Coins, рефералы и промокоды не включаются до отдельного сквозного решения.
