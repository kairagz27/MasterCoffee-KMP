# Повторная проверка — 25 октября 2026

База проверки: ветка `codex/local-mvp`, commit `4fc4706e25f1181d1a40b1f802c0d9050e119f6e`, PR #1. На старте локальный и remote SHA совпадали; пользовательских незакоммиченных изменений не было. AGENTS.md в репозитории и проверенных родительских каталогах не найден. Предыдущие результаты не заменяют проверки текущего изменения.

## Риск для основного сценария и данных

- Keystore/Keychain, чтение JSON и синхронные durable commits выполнялись из UI/ViewModel на главном потоке. Ошибки сохранения корзины/выхода могли выйти за границу обработки ошибок.
- Вход/восстановление сессии не имели общего поколения запросов: поздний ответ мог восстановить предыдущий аккаунт. Состояние busy для входа устанавливалось после запуска корутины.
- Во время нового поиска заказа кабинет сохранял действия предыдущего заказа. Оператор мог нажать оплату для старого выбора.
- Go JSON decoder принимал несовпадающий регистр и повторяющиеся ключи; null в числовом/булевом поле мог превратиться в нулевое значение административного изменения.

## Стабильность использования

- Не было корректного Back для основных экранов и восстановления выбранной навигации после завершения процесса.
- Параметры открытого напитка не переживали пересоздание Activity.
- Очередь кабинета игнорировала cursor API: заказы за первой страницей были недоступны оператору.
- Release не требовал адрес HTTPS до сборки; R8 и shrinkResources были выключены.
- Restore check сравнивал backup с текущей живой БД: новые операции после backup создавали ложное несовпадение. Не учитывались quotes и последовательности.

## Поддержка и доказательства

- После первой UI-проверки владелец отметил потерю исходного характера интерфейса и сливающийся на светлом фоне логотип. В гибридной ревизии восстановлены шторка/тени и контрастные brand/fallback-компоненты; владелец принял её на Xiaomi. Полный цикл повторён с MC-001111, дубли настроек профиля удалены. Android 16 CI проверил шторку, языки, темы и шрифт 135%; физические границы перечислены отдельно в отчёте.

- Не было Android Compose instrumentation-тестов, проверки Android Lint и release/R8 в CI.
- Не было безопасной команды создания сотрудника и готовой конфигурации будущего HTTPS-запуска с файловыми секретами.
- Не было учебного маршрута по проекту и свежих Android UI-доказательств.

## Границы среды

`adb devices -l` на старте не показывал устройств. Позже подключён Xiaomi 15 / Android 16: установка через `-r`, USB reverse, обычный холодный запуск, полный совместный пользователь/кассир цикл и настоящая durable recovery после потери HTTP 201/завершения процесса проверены. HyperOS продолжает запрещать автоматический ввод (`INJECT_EVENTS`) и запуск Activity из instrumentation (`result 102`) после подтверждённых пользователем настройки и физического переподключения; пользователь выполнял нажатия вручную. На C: было около 5,2 ГБ; пользовательский AVD сохраняется, новые локальные эмуляторы не запускаются. Предыдущие отклонённые команды очистки не повторяются.

Штатный restart Docker Desktop восстановил работу после ошибки временного `sailor-ingest.sock`. Существующий BuildKit затем обнаружил повреждённый snapshot; отдельный именованный builder собрал образы без удаления кешей/volumes и изменения default builder. Локальные Compose e2e, PostgreSQL 17, backup/restore и непустой volume изображений проверены заново. Factory reset и обход предыдущего запрета очистки не выполнялись. Сохранённый PostgreSQL 18 cluster и Go API используются для телефона; результаты отдельно от Linux CI.
