# Кабинет Master Coffee

Адаптивный интерфейс сотрудника и администратора без сборщика и внешних JavaScript-зависимостей. Использует тот же Go API, что и мобильное приложение.

Из корня проекта:

```sh
docker compose up -d --build --wait
```

Открыть http://localhost:8081. Nginx направляет `/api/` и `/uploads/` в `api:8080`; отдельный адрес API в браузере не нужен. Требуются настройки из корневого `.env.example`. Development-аккаунты создаются сервером только при включённом демонстрационном заполнении; пароль берётся из `DEMO_PASSWORD`, в интерфейсе не зашит.

Если PostgreSQL и Go API запущены нативно на `127.0.0.1:8080`, кабинет можно запустить без Docker и установки пакетов:

```sh
node admin/dev-server.mjs
```

Либо `npm run dev` из каталога `admin`. Требуется Node.js 22 или новее. Сервер слушает только loopback `127.0.0.1:8081`, отдаёт разрешённые файлы кабинета и направляет `/api/`, `/uploads/` в локальный API. Пароли и токены не записываются в журнал. Остановить: Ctrl+C. Это локальный режим разработки; Docker-образ кабинета использует nginx.

Сотрудник (`staff@mastercoffee.local`) видит очередь своей кофейни. Администратор (`admin@mastercoffee.local`) видит все кофейни и разделы «Меню», «Stories». Пользовательские аккаунты не допускаются в кабинет; окончательное ограничение прав выполняет API.

1. Найти заказ в очереди, по серверному номеру или коду из клиентского QR.
2. Проверить снимок состава, параметры, комментарий и серверную сумму.
3. Получить деньги на кассе и нажать «Подтвердить оплату на кассе».
4. Последовательно принять заказ, начать приготовление, отметить готовность и подтвердить выдачу. Интерфейс обновляется после ответа сервера.

Новые заказы опрашиваются каждые 8 секунд, пока раздел открыт и вкладка видима. Очередь разделена на страницы по 50 заказов: «Ранее» открывает серверный cursor, «К новым заказам» возвращает начало. Ошибка перехода оставляет прежнюю страницу и данные; старые активные заказы не скрыты навсегда после первых 50. Завершённый заказ можно найти по номеру. Ошибки и устаревшие данные отображаются явно. Отменить в кабинете можно только новый неоплаченный заказ.

При новом поиске номера/QR предыдущий заказ и его кнопки оплаты убираются до ответа. Ошибка поиска не возвращает действия другого заказа. Обновление очереди сохраняет клавиатурный фокус на прежнем заказе, если он остался в списке. Для просроченного/использованного QR, запрещённого перехода и других известных ошибок показана русская подсказка с дальнейшим действием; серверный код ошибки сохраняется.

Сканирование использует `getUserMedia` и встроенный `BarcodeDetector` для `qr_code`, если браузер поддерживает их. Камера доступна на HTTPS или localhost с разрешением пользователя. При отсутствии поддержки всегда доступен ручной ввод номера/кода. Камера выключается при закрытии окна, скрытии вкладки и выходе.

В «Меню» можно добавить товар с новым числовым ID, изменить описание, категорию, изображение и объёмы/цены, включить стоп-лист отдельно для выбранной кофейни. «Напиток» определяет применение скидки, а отдельный флажок «Чек повышает уровень (кофе/чай)» — участие в повышении уровня лояльности. Для нового товара этот флажок выключен, пока администратор его не выберет; участие в повышении уровня требует признака напитка. Цены вводятся в целых тенге. Создание отправляет `If-None-Match: *`, чтобы сервер не перезаписал существующий ID. Удаление из продажи выполняется через стоп-лист. Stories поддерживают создание, изменение, скрытие и удаление. Изображения JPEG/PNG до 5 МиБ отправляются в серверное хранилище; сервер дополнительно проверяет содержимое и размеры.

Bearer-токен существует только в памяти вкладки. После перезагрузки нужен повторный вход. Пароли не сохраняются. Выход очищает состояние и отменяет старые запросы; при сетевой ошибке явно сообщается, что сервер не подтвердил отзыв сессии. HTTP 401 очищает данные предыдущего аккаунта. Текст из API вставляется через `textContent`, HTML от сервера не исполняется. Nginx добавляет CSP и ограничивает встраивание страницы.

Проверки без дополнительных пакетов:

```sh
node --test admin/tests/*.test.mjs
node --check admin/app.mjs
```

Тесты проверяют сетевые ошибки/тайм-ауты без ложного успеха, истечение сессии, изоляцию ответов старого аккаунта, заголовок создания, переходы статусов и допустимые URL изображений. Локальный HTTP-сервер дополнительно проверен на обход списка разрешённых файлов, передачу авторизации/тела/статусов API, превышение размера загрузки и недоступность API.

Необязательный браузерный сценарий находится в `admin/tests/browser-smoke.mjs`. Ему нужны работающий development API/кабинет, Playwright и изолированный Chromium/Chrome. Параметры: `DEMO_PASSWORD`, при необходимости `PLAYWRIGHT_MODULE` (абсолютный путь к `playwright/index.mjs`), `BROWSER_EXECUTABLE` (путь к Chrome/Edge); команда `node admin/tests/browser-smoke.mjs`. Скрипт разрешает только localhost и создаёт/выдаёт демонстрационный заказ, а также создаёт и удаляет тестовую скрытую story. Не использует пользовательский профиль браузера. Загруженные файлы сохраняются по правилам серверного хранилища.

Свежая проверка 25 октября 2026: локальный API с настоящим PostgreSQL, вход трёх ролей, QR/оплата/приготовление/выдача, повторный QR, истечение сессии, изоляция аккаунта, ошибка обновления и восстановление, сохранение меню, загрузка изображения и создание/удаление story. Отдельный тест создаёт 51 неоплаченный заказ тестового аккаунта, проходит границу SQL cursor и отменяет эти заказы через авторизованный API. Медленный/неудачный поиск проверяет отсутствие старой кнопки оплаты; при отключённом `BarcodeDetector` работает ручной ввод номера. Проверены 1440×900, 390×844, клавиатурный переход между полями входа и увеличенный до 20 px шрифт. Новые артефакты: `admin/evidence/2026-10-25/`; подробности в `browser-smoke.json`. Старые снимки в корне `evidence/` относятся к предыдущей проверке. Это изолированный headless Chrome; Xiaomi 15, физическая камера и настоящий телефон отдельно не проверялись. Настоящее распознавание камерой требует отдельной проверки на устройстве.
